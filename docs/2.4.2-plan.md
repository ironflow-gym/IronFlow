# 2.4.2: practical weights, factual reviews and session adaptation

Local implementation on branch `2.4`, based on published release commit `26dbe15ecc3c4b8b34cde729d8c2653089a5a4b6`. Package metadata, application name and service-worker cache are set to `2.4.2`. No push or deployment is included in this development step.

## Equipment-compatible weight recommendations

The user's confirmed example is **22.56 kg starting weight + 2.5 kg + 5 kg = 30.06 kg**. A single loaded carriage with 2.5 kg increments can therefore use 22.56, 25.06, 27.56, 30.06, 32.56 kg, and so on. A paired setup with a 2.5 kg plate added on each side has a 5 kg total step instead. These are different loading arrangements and must be configured accordingly.

Exercise equipment settings now expose single load/stack/dumbbell-per-hand versus matching plates on both sides. Starting weights accept arbitrary decimals. Settings remain stored in kilograms, matching the existing form labels; imperial sessions convert both the base and increment before calculating. A configured starting weight without a step assumes 1.25 kg plates, disclosed in the form. Without explicit configuration, the app infers a loading arrangement from the exercise name; users should configure equipment where that inference is unsuitable. Plate quantities and a finite inventory are not tracked.

All recommendation paths respect the equipment grid, including same-exercise progression, different-protocol projections, related-exercise estimates, recent AI starting values and fallbacks. Historical loads cannot bypass explicit equipment settings. Warmups use the same feasible grid and cannot fall below the configured base. Plus/minus controls advance to a feasible weight in the requested direction. Exercises added by the AI during a session are calibrated through the same calculation before their sets are populated. Existing workouts retain their recorded set units if the global preference changes; the preference applies to newly created workouts. The plate display distinguishes total added load from per-side load and converts configured metric plates for imperial sessions.

Stored suggestions in older active drafts are constrained when displayed without changing recorded/completed sets. Previous values that do not fit current equipment remain visible but cannot be automatically reapplied through Keep previous values; explicit manual entry remains available. Editing equipment during a workout refreshes suggestions without silently rewriting existing sets. AI enhancement of an exercise retains its equipment settings.

The existing double-progression rep thresholds remain: increase load at the upper target, hold below the lower target, otherwise add a rep. On assisted exercises, progression at the upper target reduces assistance, rather than increasing it. Related-exercise recommendations remain labelled estimates; physical loadability does not establish that a load is appropriate for every person.

## Structured AI response validation

Every structured response passing through the shared model wrapper is parsed and validated before any caller can use it, including free and paid fallback responses. Validation covers declared shapes, required fields, arrays, enums, finite/bounded numbers, supported rep/time targets, calendar dates, set/warmup counts and optional fields. Unsupported or incomplete results fail with an actionable error. Undeclared model fields are discarded, including model-supplied IDs, completion flags and settings.

Existing template IDs and local flags are preserved during AI edits/re-optimisation. Fixed-size programme generation must return the requested session count; pre-flight and refinement cannot silently drop sessions. Pre-flight failure retains the original valid programme and shows that the review was unavailable, rather than claiming the programme passed. Valid unaffected rest/warmup settings are retained through pre-flight.

The existing free-text coaching/narrative methods are display-only and are not factual validation of AI claims. Structural validation cannot prove that generated advice is correct or appropriate. No live credentialed AI request was used for verification; public service tests and a browser workflow exercise mocked malformed responses.

## Factual weekly training review

Today → Review this week opens an offline review with previous-week navigation. It separates local calculations from optional, deterministic coaching suggestions. Each fact exposes supporting dates, exercise/session names, set values and appointment identities.

Facts include completed sessions against the current goal, planned/fulfilled/skipped/missed appointments, recorded strength working sets, volume, and comparable best estimated 1RM for the same exercise in adjacent weeks. Completed appointments are matched by exact occurrence ID; planned or skipped sessions never count as training. History and completion summaries are deduplicated using explicit session IDs, with the existing date/name grouping for older history. Current partial weeks are labelled and do not invent a recovery state.

Volume converts pounds to kilograms, excludes warmups, deloads, cardio and assistance weights, and uses dumbbell per-hand weights as recorded. Estimated strength is labelled as an estimate, with no invented trend when comparison data is missing. Coaching suggestions link back to their facts and apply nothing automatically. The review is calculated from existing records; no new cache or migration is required.

## Optional session adaptation

Workout preview and the active workout both offer Adapt this workout. Users can request a shorter remaining session, report low energy, or explicitly choose exercise substitutions for unavailable equipment. These options work without an AI key or network.

Changes appear in a preview and require Apply to current workout. Cancelling does not change the session. Shortening removes only unfinished working sets, retaining warmups, deloads, completed sets, exercise identities and at least one pending working set per unfinished exercise. If that cannot meet the time limit, the UI explains that the estimate remains above the target; it does not silently drop exercises. Duration is an estimate including rest.

Low energy targets approximately 10% less external load, rounded to available equipment increments. It never increases load and leaves assistance weights, cardio, completed sets, warmups and deloads unchanged. It reflects a user preference, not an inferred recovery diagnosis.

Substitutions require a selected library exercise of the same strength/cardio type. Exercises with completed sets cannot be replaced. Loads do not transfer between different machines or movements: the replacement starts at its configured base, or 0, with a preview notice to check its values before beginning. Changes to routines and future appointments require separate explicit editing.

A stale preview cannot overwrite subsequent set edits/completions. Applied changes are recorded in the active draft and the completion summary, which is included in local autosave, existing Drive mirrors and JSON scheduling exports. Current save-failure, retry and backup feedback is retained. Older backups without adaptation metadata remain valid.
