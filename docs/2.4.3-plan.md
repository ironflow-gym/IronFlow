# 2.4.3 — Repeat entries and saved meals

Implemented locally on branch `2.4`; not pushed or deployed.

## Approved scope

The user approved repeat meals and saved meals before recipes. They explicitly chose saved meals containing either a single entry or multiple grouped foods, with dates and quantities reviewed before logging.

## Behaviour

- Stats → Fuel offers Repeat on today's entries and entries in expanded historical dates.
- Repeating uses a focused dialog with a local calendar date, per-food quantity multipliers, live nutrition preview, and a fixed Add to food log action. Confirming creates new IDs; cancelling writes nothing.
- A compact Saved meals card opens the meal collection. Create a named meal by selecting logged foods from one or several dates; review amounts before saving. Editing supports renaming, adjusting amounts, adding foods, and removing foods. Deletion requires confirmation.
- Each saved meal stores independent nutrition snapshots. Pantry changes, original log edits, and meal edits do not silently rewrite each other. Logging a saved meal creates individual food entries; it never alters the saved defaults. Grouping for recipes, ingredients, meal-time classifications, and grams/serving conversions are outside this release.
- Calories and each macro scale independently from recorded values, rounded to two decimals. Estimated confidence and pantry provenance are retained, without re-estimation or an AI/network request.
- `ironflow_saved_meals` participates in App's atomic autosave snapshot and existing visible failure/retry handling. It is included in JSON export/restore and automatic Drive snapshots. Older backups without this key load an empty collection. Restore remains a full replacement, consistent with existing behaviour.
- Desktop Stats section wrappers now have stable React identities; saving no longer remounts nutrition children and unexpectedly dismisses their dialogs.
- Version metadata and service-worker cache advance together to 2.4.3.

## Validation

- 51 focused tests: nutrition scaling, input/date validation, fresh log identities, source preservation, and independent grouped snapshots, plus prior regression tests.
- 34 Chromium browser workflows, including repeat/cancel, grouped meal create/log/edit/delete, offline reuse, fixed mobile action visibility, single meal export/restore, older backups, failed-save retry, and mocked Drive payload inclusion.
- TypeScript and production build. Existing bundle-size and mixed ExerciseLibrary import warnings remain.
- Mobile dialogs visually checked at 360 × 640. Browser tests block service workers; this does not establish fresh offline startup or live Drive integration.

## Interface review follow-up

- Food checkboxes update the meal immediately, including selections across dates. Unchecking or removing a selected food updates the same draft; there is no separate Add selected foods step.
- Shared compact food rows show only adjusted nutrition by default. Adjust amount reveals Half / Same / Double shortcuts and a labelled amount multiplier, with original nutrition behind a further disclosure. Historical food entries do not record structured serving descriptions, so the UI does not invent grams or serving sizes.
- Meal totals stay beside Save / Add in the fixed footer. Validation errors are also in the footer and receive focus. Saved-meal logging, edit, and delete feedback appears inside the collection's visible footer.
- Log meal remains prominent in the collection. Food lists and Options (Edit / Delete) are collapsed by default. Delete still requires confirmation.
- The collection remains mounted under nested editors, retaining scroll position, open options, and keyboard focus. Deletion focuses Create saved meal if its old trigger disappears; a rename excluded by the active search returns focus to search.
- Food log headings use Today’s food and Food history. Macro text and icons are more legible; edit/delete controls have explicit accessible names, and historical date controls expose expanded state.
- Additional browser checks cover immediate cross-date selection and deselection, collapsed options, restored edit focus, mobile validation visibility, amount shortcuts, and visible feedback. Mobile creation, collection, and logging dialogs were visually reviewed at 360 × 640.
