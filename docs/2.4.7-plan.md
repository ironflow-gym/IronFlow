# 2.4.7 — Whole-exercise progression and manual weight increase

Release 2.4.7 on branch `2.4`, based on adefc74f150ec3185a9517fd139d4a77c64108eb. The user authorised committing and pushing this release. GitHub Pages deployment and live user testing remain to be confirmed.

## User decisions

- Implement progression first; training blocks follow in a separate release.
- One qualifying completed session is sufficient. Every prescribed working set must reach the upper rep target; one successful set alone is insufficient.
- Manual Increase weight remains available without qualification. Preview/apply one equipment increment to unfinished working sets, preserving reps and completed/warmup/deload sets and routine defaults. Assisted exercises use Reduce assistance.
- Without matching exercise history or a nonzero routine starting weight, show the equipment base (0 when unset) and prompt the user to choose a starting load. Do not invent a weight from another exercise.
- Future training blocks: one active block, continue until prescribed sessions are completed, not a calendar deadline. Implementation and detailed goal selection remain separate work.

## Calculation

The old algorithm selected one historical set, so 12/9/8 at 60 kg could cause an increase in an 8–12 range; reversing input records changed the result. Its separate active-exercise badge repeated that rule.

The new calculation groups completed working records by session and exercise instance, prefers the stable routine ID, and orders sessions by local date and completion time. It checks the completed-session prescription snapshot: expected working-set count, recorded set indices and rep range. All expected indices must appear exactly once and all sets must reach the upper target. One qualifying session advances one equipment increment and resets to the lower rep target. Assisted exercises reduce assistance; fractional bases, paired loading and actual set units remain respected.

Nonqualifying complete sessions hold load and build each set's repetitions within the target range. One below-range session does not automatically reduce the load. Different working loads are retained when the historical set layout matches the current prescription, rather than flattened to the first set. Warmups and deloads are explicitly excluded; the old statistical warmup heuristic is no longer used for progression (existing analytics retain their own rules).

Partial/duplicate/ambiguous records, changed set counts/ranges and unconfirmed routine context cannot qualify an automatic increase. Legacy records are retained unchanged and can supply starting references, but missing prescription data is never inferred. Different exercises do not transfer load via categories, percentages or estimated 1RM. The old single-set progression helper was removed after its application callers were replaced.

## Completion and compatibility

New completed history records optionally retain exerciseInstanceId, workingSetIndex, prescribedWorkingSets and prescribedRepRange. They are written atomically with workout history and removal of the active draft by the existing App autosave. The prescription is the workout's explicit working-set layout at completion, including user edits/adaptations. Warmups/deloads remain classified and excluded from qualification.

Recommendations carry per-set suggested/previous values, an action and a calculation version. New workouts initialise per-set values; suggestion/previous actions map by working-set position and preserve completed sets. Older active drafts get a current explanation without rewriting their existing values; obsolete recommendation explanations are not presented as routine notes.

All optional metadata travels through existing JSON/Drive snapshots and restore/recovery handling; older backups still load. No cloud/network or AI is required for these calculations. Calendar completion identity and historical names remain unchanged.

## Interface

The existing suggestion disclosure shows last and suggested working sets where needed, with a short explanation. The active badge uses the same recommendation action. Increase weight / Reduce assistance sits alongside existing choices in active resistance exercises; no new navigation destination or additional per-set buttons. Preview uses the shared native Modal with grouped load changes, clear units and per-hand dumbbell conventions, Cancel and a fixed Apply action. Cancel changes nothing; apply preserves repetitions and routine defaults. A stale exercise preview is rejected.

## Follow-up UI review

The user chose literal previous-set copying with a clear source label, and requested a compact, attractive active screen.

- Increase weight / Reduce assistance is visible beside the collapsed explanation. The explanation uses one small previous/suggested table rather than repeated lists; per-hand units and equipment steps stay explicit. Manual choices show Selected values and clear the stale starting-load prompt, including direct set value edits. Application labels refer to the current exercise.
- Mobile exercise names use the available width with a separate compact toolbar; advice/history/instructions have accessible names and 44px targets. Completed rows retain readable values. The equipment action uses one short line.
- The number pad and nested plate details use the shared native Modal with focus trapping/return, Escape, scrollable content and a fixed Apply value footer. Plate diagrams are collapsed until requested. Numeric semantics and plate calculations are retained.
- Classification uses the explicit keyboard-accessible selector. Numbered markers no longer duplicate that interaction. An explicit delete button confirms before removing an unfinished set, replacing the hidden long-press gesture. Completed sets are not offered deletion.
- Copy warmup / Copy working set / Copy deload names the preceding set number, copies that literal set's values and never changes the receiving classification/completion.
- Discard workout confirms before removing an unfinished workout; Finish workout and Add exercise replace older jargon. Deload and warmup sets cannot show immediate PR badges, including after a classification correction.
- Added browser coverage for source-labelled copying, mobile targets/layout, numerical editor cancel/apply/focus, nested plate dialogs, manual prompt correction, keyboard classification, delete/discard confirmation and deload PR suppression.
