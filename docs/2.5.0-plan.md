# Release 2.5.0 — training blocks and daily workout interface

Base: `fc8b42d037e2685d75df3b5aeff295823fa14440`, existing branch `2.4`. Release prepared for the user-authorised push to `2.4`. Version, metadata and service-worker cache are 2.5.0. GitHub Pages deployment and user review follow the push.

## Entry points

- Today → Manage routines → Create training block: three-stage setup, workout choices, review.
- Today → View block: rounds, session start/preview, collapsed options, schedule/skip/assignment, future edits and factual results.
- When all sessions are resolved: Review finished sessions → Finish block, then reuse the programme with new identities.
- Food → Review block nutrition, or View block → Review previous Food settings: compare and explicitly accept restoration.

## Implementation

`src/trainingBlocks.ts` owns independent programme/session identities, validation, completion/skip sequencing, future snapshots, local-date scheduling, conflicts, facts, goal policies and physical weight conversion. `TrainingBlockBuilder`, `TrainingBlockManager` and `BlockNutritionComparison` use existing modal controls and progressive disclosure. No new main navigation item.

App hydrates and atomically autosaves `ironflow_blocks` with history, calendar and workout draft. Exact session links distinguish fulfilment from partial attempts and ordinary workouts. JSON/Drive backup and restore/undo carry block records. Older snapshots have no inferred blocks. Failed local saves retain the existing retry feedback. A partial attempt logged without fulfilment leaves its planned appointment unresolved.

Fixed/timed prescriptions bypass automatic strength progression. Timed holds retain physical load and seconds, and are excluded from strength/volume calculations. Current workout snapshots and source routines are preserved during future edits. Existing compact workout set controls and manual increase icon remain intact.

## Daily workout interface refinements

The active workout uses a compact sticky session header with block/round context, duration, adaptation and an always-reachable Finish/Discard action. Rest occupies a reserved header row, replacing the floating overlay; all timer controls use 44px targets. The final set focuses Finish. Change exercise and manual weight increase remain adjacent; coaching/history/instructions expand from More options. Set gestures and literal previous-set copying remain unchanged. Comparisons share their date where possible, retaining explicit dates for exceptions.

Mobile numeric controls keep full-height targets with less surrounding spacing. Completed sets remain readable. Names wrap in daily views. Timed editing uses explicit seconds and matching target labels; changing tracking clears the value for deliberate entry, with validation before saving. Both workout editors confirm discard. Block reviews format converted weights and fixed previews group identical prescriptions. Block administration and the persistent Food restoration panel remain deferred.

## Validation

Focused tests cover sequence, identity, partial fulfilment, source isolation, future snapshots, local-date calendar expansion, multiple appointments/conflicts, goal mappings, physical unit conversion, malformed records, older backups and Food snapshots. Browser workflows cover creation, completion, out-of-order work, skip/undo, calendar priority, partial choices, optional Food changes/restoration, seconds and units, mocked AI count rejection/context, failed-save retry offline, JSON restore/undo, active snapshot protection, explicit assignment and repeat. Final checks after the daily UI refinements: **84 focused tests and all 87 Chromium workflows passed**. TypeScript/production build and `git diff --check` passed. Existing bundle-size/mixed-import warnings remain. The new workflows check 320px set controls and unobstructed rest, finishing with exertion recording, and timed editing/discard protection on mobile and desktop. Ordinary mobile logging, editor fields and long names were visually reviewed; Today, block management and workouts have no horizontal overflow in the long-name check. In the same 390px example, the first set moved from about 502px to 274px down the page, and later rows from about 166px to 134px. The remote branch was checked before release preparation; no newer remote work was present.

## Limits

Live AI programme quality and live Drive round trips are not established by mocked browser tests. Offline tests start from an already loaded app, with service workers blocked for deterministic mocks; they do not verify cold offline PWA startup. Block reviews show recorded facts, not measured physiological or event outcomes. Goal/round structure changes use end/new block; future workout prescriptions are editable. Cross-device and selective merging remain deferred.
