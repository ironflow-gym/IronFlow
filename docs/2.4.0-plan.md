# IronFlow development plan

Stable baseline: branch `2.3.1`, commit `fc0d2120e9c9122345b5bf9b0f28cef1d79a73fb`.
GitHub testing branch: `2.4` (created from the local `2.4.0` development branch).
Changes are reviewed and validated before release.
This document records the 2.4.0 scope. Application release numbering was subsequently
aligned to 2.4.1; see [the 2.4.1 implementation notes](2.4.1-plan.md).

## Current scope: 2.4.0

### Protect existing workflows

- Add repeatable tests for persistence failures, backup ordering, progression,
  workout completion/recovery, routine creation and backup export/restore.
- Add Chromium browser checks and CI instructions.
- Preserve the existing IndexedDB schema and JSON backup format.

### Reliable local saves and cloud backup

- Commit related state together, including completed history and deletion of its draft.
- Resolve writes after transaction commit, reject failed reads, and stop boot autosave
  if existing data cannot be read.
- Show local saving/saved/failed status, retain failed edits for retry, and warn
  before leaving while changes are unsaved. Failed edits are retained in memory;
  they cannot survive closing the tab when browser storage cannot accept them.
- Serialize cloud uploads after local commits; persist pending revisions in
  IndexedDB; retry transient failures and resume on reconnect.
- Preserve pending changes made during an upload. Require reauthorization when
  silent token refresh fails. Pause backups during restore.
- Keep internal backup metadata out of exported and uploaded records.

### Faster workout logging

- Add one-action repeat of the previous set's values without copying completion
  or changing the target's warmup/deload classification.
- Show previous matching sets with dates and converted weight units.
- Increase mobile adjustment targets, fix sustained press adjustment, add keyboard
  access and explicit set classification selectors.
- Preserve existing cardio, rest timer and session exertion behavior.

Acceptance: focused tests and production build pass; existing records remain readable;
failed saves are visible; backups contain committed edits; unfinished workouts resume.
Live Google authorization and AI calls need separate credentialed verification.
Browser API tests mock Drive and disable service workers so mocks are deterministic;
they do not establish full offline PWA startup or live cloud integration.

Current implementation checks: 12 focused tests and seven Chromium workflows pass;
TypeScript and the production build pass. Existing Vite chunk-size and mixed-import
warnings remain. The mobile layout was checked at 390px with no horizontal overflow.
The CI workflow has been added locally; it has not run on GitHub yet.
