# 2.4.9 — Mobile menu visibility fix

Release 2.4.9 on branch `2.4`, based on 49c68d995022eb4bceb5d70481c95b12c0997dc5. The user authorised committing and pushing this release. GitHub Pages deployment and live user testing remain to be confirmed.

The hamburger could change to a cross without displaying its actions whenever an unfinished workout existed. The button allowed access outside the active-workout tab, while the dropdown separately required no active session at all. Both now share one visibility condition, so the dropdown exists whenever its button is available and open. Existing active-workout-tab visibility is retained. The button also identifies the controlled dropdown with aria-controls.

A browser regression reproduced the missing Settings action before the fix. Navigation checks cover opening/closing the menu on Today, Food and Stats with and without an unfinished workout, selecting Vault Backup, closing the dialog and preserving the workout draft. Existing mobile/desktop draft/navigation and midnight checks remain included.

Training-block decisions were recorded separately; no block, scheduling or Food-target implementation is part of this fix.

Validation passed: all five navigation browser workflows, 70 focused tests, TypeScript and production build. The new regression failed before the fix and passed afterwards. Existing Vite size/mixed-import warnings remain. `git diff --check` passed.
